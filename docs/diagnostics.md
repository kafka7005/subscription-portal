# Диагностика операций

Для квитанций покупки и продления сначала установите кастомный модуль версии 1.6.0 или выше, затем обновите сайт. Для загрузки новой версии модуля требуется перезапуск службы бота.

## Смена ссылки

Под одним полем `op` модуль записывает источник действия, этап и время от начала операции. Чтобы посмотреть последние этапы на сервере с systemd, выполните

```sh
journalctl -u bot.service --since '1 hour ago' --no-pager | grep -F '[Site:Rotation]' | tail -n 30
```

При записи в файлы ищите ту же метку в журнале сайта бота. Событие `panel_confirmed` обозначает подтверждение панели Remnawave, `link_committed` — фиксацию изменения в базе, `telegram_accepted` — принятие сообщения Telegram. При `telegram_result_unknown` Telegram мог получить сообщение до обрыва соединения. После проверки действующей ссылки можно отдельно повторить уведомление в админке.

## Платежи и ошибки сайта

Если ответ о покупке или переводе потерян, откройте проверку статуса. Запрос статуса доступен владельцу операции. При неопределённом результате сначала сверьте историю платежей или баланса. Для поддержки достаточно номера операции. При ошибке интерфейса скопируйте код из окна ошибки. В штатном API отчётов сайта он указан в поле сообщения как `Incident` и восемь символов. При получении от API номера запроса интерфейс также показывает его после косой черты.

## Если учётные данные попали в старый журнал

Защита Loguru и стандартного Python-логгера включается при загрузке модуля. Ранее записанные файлы и копии сохраняют своё содержимое. Ограничьте доступ к затронутым архивам, согласуйте замену секрета с владельцем и проверьте штатную работу после применения. Проверяйте маскирование на вымышленных данных. Передавайте в поддержку код события, этап и время.
