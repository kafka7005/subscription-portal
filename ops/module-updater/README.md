# Обновление модуля из админки

Служба рассчитана на Linux с systemd, Git, Python 3.9+ и glibc с renameat2. Установите её на машину с ботом. Для контейнерного бота с управлением через Compose используйте ручное обновление модуля по инструкции проекта.

## Первое подключение

1. Вручную установите версию модуля 1.7.0 или новее из того же репозитория, что и сайт. Согласуйте перезапуск бота для загрузки API. Достаточно одного установленного экземпляра модуля.
2. Из клона этого репозитория на сервере бота выполните команды ниже. Укажите каталог установленного бота, имя службы и порт его локального HTTP API. Для закрытого репозитория заранее настройте на сервере ключ развёртывания с доступом на чтение и проверку ключа SSH-хоста. Служба запускается от root. Для открытого репозитория достаточно HTTPS. Используйте адрес origin без встроенного пароля или токена.

~~~bash
git pull --ff-only
sudo bash ops/module-updater/install.sh /root/bot bot.service 3004 "$(git remote get-url origin)"
sudo systemctl status portal_custom_api-updater.timer
sudo journalctl -u portal_custom_api-updater.service -n 30 --no-pager
curl -fsS http://127.0.0.1:3004/api/portal/module-update/version
~~~

3. После обновления сайта откройте **Админка → Сайт → Обновления → Модуль бота**. При первом подключении без доступной новой версии отображаются две одинаковые версии. Установщик службы проверяет источник и запускает таймер. Перезапуск самого бота при первом подключении выполняет оператор.

## Выпуск и установка версии

При выпуске повысьте номер в `bot-module/portal_custom_api/VERSION` в формате X.Y.Z и опишите изменения в соседнем `RELEASE.txt`. Публикуйте обе правки вместе с кодом в main. Служба проверяет источник раз в три минуты. Администратор видит описание, нажимает **Обновить модуль** и подтверждает перезапуск. Если main изменился после предпросмотра, кнопка требует нового подтверждения.

Служба берёт только каталог модуля из подтверждённой ревизии. Она проверяет синтаксис, меняет каталоги местами и запрашивает версию у загруженного API после перезапуска. Предыдущая копия находится в `/var/lib/portal_custom_api-updater/private/previous` после успешной установки. Хранилище службы и каталог модуля должны находиться на одной файловой системе, поддерживающей атомарный обмен каталогами. Локальные настройки держите за пределами каталога распространяемого модуля.

Если новая версия не запустилась, служба возвращает предыдущий каталог, перезапускает бота и проверяет восстановленную версию. После аварийной остановки воркер использует журнал незавершённой установки при следующем запуске. Если откат не подтвердился, восстанавливает оператор. Сначала проверьте журналы обеих служб и файлы в каталогах модуля и предыдущей копии.

~~~bash
sudo journalctl -u portal_custom_api-updater.service -u bot.service --since '15 minutes ago' --no-pager
sudo systemctl disable --now portal_custom_api-updater.timer
~~~

После ручного восстановления проверьте локальный URL версии, сохраните журнал `private/transaction.json` вне рабочего каталога службы и только затем снова включайте таймер. Повторный запуск install.sh обновляет саму службу. Веб-интерфейс обновляет только модуль.
