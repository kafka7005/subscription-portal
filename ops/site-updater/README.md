# Обновление из админки

На сервере сайта один раз подключите две службы systemd. Шлюз проверяет cookie через HTTPS и штатный /api/auth/me, а отдельный процесс от имени владельца клона проверяет upstream и запускает scripts/update.sh. Сборка должна работать у этого пользователя. Службе сборки предоставляется доступ к группе docker. Устанавливайте её только для доверенного локального владельца исходников.

Для старой установки получите код командой git pull --ff-only. Для внешнего веб-каталога добавьте --web-root с его путём к команде первичной сборки. Из корня клона на Ubuntu с Docker выполните:

```bash
sudo apt-get install -y rsync python3
bash scripts/update.sh  # получить интерфейс обновлений в установленной статике
sudo bash ops/site-updater/install.sh https://portal.example.com "$PWD" "$PWD/dist"
sudo docker compose up -d --force-recreate site
sudo systemctl status portal-update-api portal-update-worker --no-pager
```

Подставьте точный HTTPS-адрес портала. При внешнем Caddy укажите его рабочий каталог вместо "$PWD/dist". Добавьте в блок сайта перед обработчиком статики:

```caddyfile
handle /_site-update/* {
    reverse_proxy unix//run/portal-site-updater/api.sock
}
```

Если внешний Caddy работает в контейнере, подключите каталог /run/portal-site-updater в тот же путь контейнера в режиме ro. Примените конфигурацию Caddy штатным способом. В стандартном Compose маршрут и том уже описаны. После изменения самого файла службы или его Python-кода повторите установку служб.

Откройте **Админка → Сайт → Обновления**. Проверка источника выполняется каждые три минуты. Старая сборка без отметки ревизии покажет «Версия не записана» до первой установки. После успешной сборки сравнивается версия в раздаваемой статике. На вкладке показаны очередь, установка и результат. При ошибке посмотрите журнал на сервере:

```bash
sudo journalctl -u portal-update-worker -n 80 --no-pager
```

Для отката статики используйте штатный scripts/update.sh --rollback с тем же --web-root. Модуль бота обновляется отдельно. Отключить обслуживание кнопки можно командами sudo systemctl disable --now portal-update-api portal-update-worker.

### Описание версии до установки

Из корня обновлённой доверенной копии репозитория выполните один раз во время простоя установщика:

```bash
sudo install -m 0644 ops/site-updater/worker.py /usr/local/lib/portal-site-updater/worker.py
sudo systemctl restart portal-update-worker
```

Откройте в админке «Сайт → Обновления». Служба читает `docs/release-notes.json` из полученной версии Git. Для выпуска добавьте запись в начало списка с новым постоянным `id`, заголовком `title`, списками `changes` и `verify`. Старые записи сохраняйте. Для установленной версии показывается последнее описание, для обновления — все новые записи с момента установки. При первом переходе со старого интерфейса описание можно заранее прочитать в этом файле репозитория.

Для выпуска «Обновления, диагностика и история клиента» также обновите модуль на сервере бота. Из каталога `bot-module/portal_custom_api/` этой версии перенесите `customer_tools.py`, `support_tools.py` и `VERSION` в установленный каталог `modules/portal_custom_api/`, затем перезапустите службу бота. Если модуль устанавливается впервые, установите каталог целиком. Миграция базы для этих двух методов чтения не требуется.
